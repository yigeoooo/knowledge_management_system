# 小维：自然交流与知识库问答

机器人在原有首问、续问接口上支持自然交流，不增加客户端参数。回答仍为一段简洁纯文本。网页知识问答继续使用原来的资料问答流程。

## 流程与边界

机器人先经过 LangGraph 的 `route_interaction` 节点，结合当前问题、本会话历史与知识库领域判断意图：

| 类型 | 处理 |
| --- | --- |
| `chat` | 问候、感谢、自我介绍、闲聊和用户自述的记忆，直接自然回复。 |
| `general` | 与具体业务无关的稳定通识，直接简洁回答。 |
| `realtime` | 当前天气、路况等需要实时数据的问题，明确说明尚无实时查询能力。 |
| `knowledge` | 产品、票价、开放规则、具体资料等业务问题，继续理解追问、检索、生成及证据核验。 |
| `clarification` | 对象不明确且历史无法确定时，简短澄清。 |

直接交流由分流调用同时生成回复，经 `direct_answer` 节点清理为纯文本，不做向量检索或伪造引用。天气类能力说明由服务端固定，不能透传模型凭空生成的实时晴雨、温度。没有接入天气 API，也没有增加语音合成。

“你好，套票多少钱”应走知识库；“为什么下雨”是通识；“景区雨天是否开放”仍查询业务资料。缺少业务证据时给出小维的简短说明，不转为通识猜答案。分流调用失败或结构无效时记录异常并回退知识库，诊断中保留回退原因。

意图判断属于模型判断，仍需通过实际领域的测试题检查边界。机器人问题增加一次分流调用，超时预算为20秒；闲聊回复在同一次调用完成。

## 提示词、记忆与追踪

- `robot_persona` / **机器人身份与表达**：自称“小维”，自然、友好、简洁；在机器人分流、业务答案生成和追问澄清时使用。
- `robot_interaction` / **机器人交流与分流**：决定问题类型，并生成闲聊与通识回复。

两者均存入 PostgreSQL 的 `prompt_templates` / `prompt_versions`，页面可查看、保存版本和试测。此次迁移创建两份功能初始 v1，不覆盖原有已发布提示词。后续变更仍必须通过现有评测与人工确认后发布。

每轮沿用现有不可变提示词快照。旧任务快照缺少新增用途时保持旧流程，不临时混入当前版本。新对话及新提交的轮次使用当前发布组合。

所有直接交流同样写入 `qa_logs`，保存 `answer_kind`，进入当前会话的近期历史与摘要；新会话不共享记忆。机器人接口和会话 ID 的使用方式不变。问答日志、逐题对比与流程详情显示回答类型，LangSmith / 本地步骤显示意图判断和直接交流。

### 调整会话记忆

在 `knowledge_back/.env.local` 添加或修改下列配置，重启后端及独立 worker 后生效：

正常启动按“进程环境变量 → `.env.local` → 代码默认值”的优先级取值。`.env.example` 和 `.env.server.example` 只是配置模板，不会被自动读取或用于补齐缺失字段。若启动脚本已导出同名环境变量，需要同步调整它。

```dotenv
QA_RECENT_TURNS=6
QA_HISTORY_BUDGET=9000
```

`QA_RECENT_TURNS`（1–20）控制保留原文的最近已完成问答轮数，一轮包含一个问题和回答。超过该轮数时，更早且尚未归入摘要的问答，与已有摘要一起滚动更新；不是每6轮才生成一次，也不是只记住6轮。每次最多读取64轮待整理记录，摘要输入还受约18000字节限制，避免旧长会话一次处理过多。

`QA_HISTORY_BUDGET`（1000–32000）是本次传给模型的摘要和近期历史 JSON 的 UTF-8 字节预算，不是 token 数。摘要占用超过预算的一半时会截短，近期原文也按剩余预算选取。因此调大保留轮数时需要结合预算调整；普通中文字符通常约3字节。摘要提示词正文在“提示词管理 → 会话摘要”修改。

知识问答和机器人问答页不再在答案下方显示内部上下文截短提示。总轮数超过200（第201轮起）时，输入框上方显示建议开启新对话的提示和按钮；当前对话仍可继续，开启新对话后从独立记忆开始，旧对话保留在历史中。提醒采用服务端返回的总轮数，不受前端历史分页影响。这是网页提醒，机器人接口不自动切换会话，也不把提醒拼入回答。

## 评测

机器人测试题新增可选的“预期回答类型”。自动指标新增回答类型准确率；闲聊题无需指定预期文档，可填写参考答案或要点。正式评测与单题测试都执行同一机器人流程，保留题目的历史上下文。

结果记录 `answer_kind`、`used_prompt_keys` 和 `routing_fallback`。两侧卡片显示实际使用的提示词，完整冻结组合仍可展开查看。未实际执行的用途不能据此发布，例如只测试“你好”不能证明 `answer_robot` 合格；交流分流发生异常回退时不能发布该分流版本。

运行条件版本更新为 `rag-v2-prompts-v4-robot-interaction`，旧实验保留，但不能用于本流程的新版本发布。建议在同一知识库唯一评测集中启用问候、身份、感谢、通识、天气、混合问题和带历史的业务/闲聊追问，逐题确认。

样例定义位于 [robot-interaction-examples.json](../evaluation/robot-interaction-examples.json)。当前部署已将9道样例追加到机器人绑定知识库现有评测集，状态为草稿；原有题目和人工标注保留。业务样例需要管理员按实际文档补充依据后启用。

## 部署

```bash
cd knowledge_back
uv run flask --app app db upgrade
```

迁移版本为 `f73a20bd961e`；新增提示词种子与回答类型字段说明，没有新增业务表。`init.sql` 同步了相同初始提示词、字段说明和版本号。升级后重启后端与独立 worker，前端重新构建或刷新开发页面。
